# Rules for ÀṢẸ Development

- **Ideation stays in chat — never commit ideation docs.** When asked to brainstorm/ideate/rank ideas (game-differentiation ideas, card ideas, feature ideas, etc.), answer directly in the chat reply; do **not** create a markdown file, commit it, or open a PR for it. Deliverables are code changes, not idea docs. (The one legacy exception, `docs/design/card-ideas-2026-07.md`, predates this rule — don't add new siblings to it.)
- Always use the `gpt-image-2` model for all image, sprite, and background art generations.
- Never use Gemini or any other image models for generating assets.
- **OPENAI_API_KEY location**: the key for live asset-generation runs lives in the gitignored `.env` at the primary checkout's repo root (`~/spire/.env`). Worktrees don't inherit it — symlink it in (`ln -s <primary-checkout>/.env .env`). The `tools/gen-*.js` scripts read `process.env.OPENAI_API_KEY` directly and do **not** auto-load `.env`; load it via `node --env-file=.env tools/gen-<x>.js` (Node ≥ 20.6) or `set -a; source .env; set +a`. Never commit the key.
- **Syntax Check**: Before committing or deploying, always verify modified JavaScript files using `node --check <path_to_file>` to catch syntax errors like unclosed blocks or brackets.
- **Tests & CI**: two plain-Node suites (the game stays zero-dependency) — `npm test` (`tools/test.js`, fast DOM-free logic: rng/run-state/mapgen/cards/combat) and `npm run smoke` (`tools/smoke.js`, headless-browser e2e that boots the site and drives title → New Run → character → map → combat, failing on any uncaught JS/console error; uses ambient Playwright, not a project dep). Both run in CI on every push/PR via `.github/workflows/check.yml` (Playwright+Chromium installed only in CI). Confirm the check run is green before self-merging to `main`, since the merge auto-deploys.
- **No `gh` CLI / GitHub MCP fallback**: desktop sessions may have neither the `gh` binary nor a GitHub MCP server. Since `git push` works, the credential helper has a usable token — extract it with `printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p'` and drive the REST API directly (`POST /repos/dermosef91/spire/pulls` to open a PR, `GET /repos/.../commits/<sha>/check-runs` to wait for CI, `PUT /repos/.../pulls/<n>/merge` to merge). The token cannot dispatch/rerun workflows.
- **Events ("?" nodes)**: Story events live in `src/data/events.js` and must be original to the ÀṢẸ world (Sunken Market / Brass Archive / Static Crown) — never reskins of Slay the Spire events. Each event has an `art` id; the view (`eventArt()` in `game.js`) shows `assets/event-art/<art>.png`, falling back to a committed `.svg` placeholder, then the generic "?" glyph. Generate art with `node tools/gen-event-art.js` (reads `tools/events.manifest.json`); `--dry-run` writes SVG placeholders with ZERO deps.
- **First-play tutorial**: `src/ui/tutorial.js` (`CombatTutorial`) is a single top-pinned coaching banner shown once, on the first-ever combat, gated by `meta.tutorialDone` (set true when finished OR skipped). Started from `beginCombat` in `game.js` ~1700ms after mount (timed to clear the deferred Battle-Start-then-opening-draw open). It reads live combat state by chaining `combat.onUpdate` (never mutates game logic) and never blocks the board. Six steps: hand+Àṣẹ intro, enemy intent, play a Block skill, play an Attack card, end turn, wrap-up — each of steps 1-5 adds a `.tut-highlight` class (a bright pulsing shine — `filter: brightness()/saturate()` + glow `box-shadow` via `@keyframes tutShine`, deliberately not a static outline/box) to the relevant live DOM node(s) by selector via `querySelectorAll` (step 1 highlights every card in hand individually with `.hand .card`, not the whole `.hand` container as one box), reapplied every `onUpdate()` since combatView rebuilds those nodes each render. The enemy-intent step also sets `align: 'left'` on its step config (toggles `.tut-banner.tut-left`) so the banner doesn't overlap the intent pill it's pointing at on narrow/landscape-phone widths — verified no bounding-box overlap at 812×375, 700×780, 390×780. The block/attack steps find the first matching card in hand by `uid` and advance only when that uid leaves the hand (falls back to "any card played" if no match exists, ~2-3% chance on a 5-card starter draw, so it can't soft-lock). `game.js`'s `startMonster()` forces the run's first-ever monster fight to `['husk_drone']` when `!meta.tutorialDone` so the guaranteed turn-1 attack intent makes the "foe is about to strike" step always true. Re-test by clearing `localStorage`. Styles under the "first-play tutorial" block in `styles.css`.
- **Auto-Update Learnings**: On every action/task, if you discover a project-specific gotcha, solve a debugging issue, or establish a new convention/pattern, you must immediately update `CLAUDE.md` and `.agents/AGENTS.md` to persist this learning.
- **Landscape-phone breakpoint (`@media (max-height: 560px)`)** is the single hook for short viewports; see the detailed note in `CLAUDE.md` before touching `.title`, `.charselect`, or `.hand`/`.combat-controls` layout — CSS cascade order (not media-query nesting) decides which override wins, and `.combat-controls` uses fixed screen-relative positions that `.hand` must track with matching `%`-based `calc()` math, not `100vw`. `.charselect` here is a CSS grid (Back button + heading overlapped in one `grid-row/column: 1` cell, card row `minmax(0, 1fr)` to fill leftover height) — two gotchas: grid auto-placement needs **both** axes explicit on overlapping items or it bumps the second into a new implicit column instead of stacking them, and per-card sizing must avoid `vh` when the row's height depends on optional sibling content (the Ascension selector) — use `%`-of-width + `aspect-ratio` for the glyph and `flex-shrink: 0` on text blocks instead, or `flex-shrink` silently squashes a `-webkit-line-clamp` box below its line height and clips text mid-word; a `.charselect:has(.asc-select) …` preset (same `:has()` pattern as relic/potion art) handles the "meaningfully less height available" case separately.
- **Browser testing**: install `playwright-core --no-save`, launch Chromium at `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` (which falls back to the default macOS Google Chrome location on Darwin) with `--no-sandbox`. Never wait on `networkidle` (looping audio/rAF never idles) — use `domcontentloaded` + `waitForTimeout`. `window.__ase` is the live Game instance for asserting run state **and driving scenes**: `__ase.showTitle()`, `__ase.showCharSelect()`, `__ase.startRun('amara')`, `__ase.showMap()`, `__ase.startMonster()`. Set `localStorage` `spire_of_ase_meta_v1` `tutorialDone:true` before combat so the first-play tutorial doesn't block screenshots. Also, when selecting cards dynamically via Playwright (e.g. during tutorial coaching steps), avoid using dynamic styling classes like `.tut-highlight` directly in click locators. Because the hand is cleared and rebuilt on changes, these classes can be temporarily missing until next-tick updates reapply them. Instead, fetch the card's `data-uid` attribute first and target the element specifically using `[data-uid="..."]`.
- **Interactive preview tool (`mcp__Claude_Preview__*`) gotcha**: scenes fade in via `.scene{opacity:0;transform:translateY(14px)}→.scene.show{...}` (`setScene()` in game.js). Driving a scene via `preview_eval` and measuring `getBoundingClientRect()` right after — even past an in-page `setTimeout` wait — can still catch it mid-transition (rAF seems throttled on these tabs), producing a phantom few-px offset. Force the settle before measuring: `el.style.transition='none'; el.style.opacity='1'; el.style.transform='none'`.
- **QA screenshot / responsiveness audit**: `npm run qa` (`node tools/qa-screenshots.js`) drives title → char select → map → combat at a landscape phone (812×375) and a desktop (1366×850) viewport, writes JPEG screenshots + `report.md`/`report.json` to `docs/qa/`, and flags horizontal overflow, off-screen/clipped controls, and hand cards overlapping the energy orb / End Turn. Clean run = `0 issue(s)`; committed `docs/qa/*.jpg` are the baseline. It found & we fixed a real desktop-combat bug: the fanned hand was cropped at the bottom and slid under the corner controls. Fix lived in the base `.hand`/`.card.in-hand` rules (bottom padding 30px + dip cap `min(--shift,18px)`) plus the desktop breakpoint (safe-zone margins **and** a smaller `--card-h` cap — margins alone can't help because `.hand` is `justify-content:center`, so the whole rotated hand must actually fit the band between the controls).
- **Combat transitions / pacing** (added here): node entry runs through `Game.veilTransition(swapFn)` (a `.scene-veil` fixed fade veil) so combat/events don't snap in. Combat **opens deferred** — `CombatView.mount` shows a "Battle Start" banner then calls `combat.start()` ~650ms later, so the opening draw deals card-by-card *after* the popup; the tutorial kickoff in `beginCombat` (~1700ms) is timed to that, so keep them in sync. Two cosmetic engine events drive the pacing text: `fx('announce',{text,kind})` → `CombatView.announce()` centered banner (`battle`/`player`/`enemy` = Battle Start / Your Turn / Enemy Turn), and `fx('enemyMove',{source,name})` → move name floated over the enemy via `floatText(...,'name')`. `combat.js`'s `enemyPhase` **`await`s** after the Enemy-Turn banner (850ms), after each move-name float (750ms), and after each action resolves (550ms) so the strike never lands the same instant it's announced — preserve those waits. `endTurn` adds one more `await wait(600)` after `enemyPhase()` returns and before `startPlayerTurn(false)`, so "Your Turn" doesn't fire in the same instant the last enemy's hit lands (skipped when `this.over`). Card play is **two-tap**: first tap sets `previewCard` (card straightens + enlarges via `.previewing`; `--angle/--shift` zeroed in `renderHand`), second tap commits; drag-to-play bypasses the preview. All of it honors `prefers-reduced-motion` (banner/veil have fade fallbacks). **Gotcha**: `npm run qa` wipes `docs/qa/`, deleting the committed `docs/qa/README.md` — `git checkout -- docs/qa/README.md` before committing.
- **Crowded-hand overlap**: `CombatView.applyHandSpacing()` (`src/ui/combatView.js`, called from `renderHand()` before the rAF-deferred draw-pile fly-in reads positions) replaces the hand's flexbox `gap` with per-card `margin-left` once the fanned hand's natural width (card width × N + gap × (N-1)) exceeds `.hand`'s available width, so cards overlap (capped at 55% of a card's width) instead of overflowing into the pinned energy orb/End Turn or relying on `.hand`'s horizontal scroll. A hand that already fits computes the same margin as the original gap, so it's a no-op there. Hover/`.selected`/`.previewing` already raise a card's `z-index` and the two-tap preview straightens+enlarges it, so an overlapped card can always be read in full. Mobile landscape (`@media (max-height: 560px)` in styles.css) also pulls the energy orb, End Turn (shrunk ~13% just there), and draw/discard/consume piles closer to the screen edges, with `.hand`'s margins recomputed to match — see the comment above `.hand` in that block before changing either side's geometry.
- **`Combat.notify()` coalescing (real bug found & fixed here)**: several call sites fired two synchronous `notify()`s in the same tick (e.g. `startPlayerTurn`'s `draw()` fires one internally, then the method fires another right after to refresh the log). `CombatView.renderHand()` fully rebuilds the hand's DOM on every call, so the second same-tick render destroyed the first render's newly-hidden new-card nodes before their `requestAnimationFrame`-scheduled draw-pile fly-in animation could run — cards ended up in the right spot but silently teleported instead of animated, on every draw (including the opening hand) since the fly-in was added. Fixed by making `notify()` coalesce same-tick calls via a microtask (`Promise.resolve().then(...)`, guarded by `_notifyScheduled`) into one deferred `onUpdate()`. Because of this, `tools/qa-screenshots.js`'s `combat` scene `settle` had to go from 1100ms to 1800ms — the fly-in now actually takes ~830ms after the 650ms deferred `combat.start()` to fully land. If a per-card/per-element cosmetic animation you add silently doesn't play despite the underlying state change happening, suspect a same-tick double-render stomping a pending `requestAnimationFrame` before you reach for anything more exotic.
- **Animated background** (`src/fx/background.js`) exports a `background()` singleton controller: `setAct(act)`, `setCombat(on)`, `pulse(kind, power)`. It's act-themed (palette per act) and reacts to combat FX; keep new pulses reduced-motion-safe.
- **Ascension** lives in `core/state.js` (`ASCENSION_LEVELS`, `MAX_ASCENSION`, `run.enemyHpMult`, `run.enemyDamageMult`, `run.restHealFraction`). Levels are cumulative; unlocked one at a time by winning at the current max. Meta keys: `maxAscension` (unlocked) and `ascension` (last selected). The ascension picker in `game.js` renders straight from `ASCENSION_LEVELS`, so adding a level is just appending an entry there plus wiring its modifier at the right hook (HP → `enemyHpMult`, per-hit damage → `enemyDamageMult` applied in `combat.enemyAttack`, one-off run/combat setup → `RunState` constructor or `combat.start()`).
- **Encounter modifiers + reactive map (#18) & nemesis (#19)**: `beginCombat(ids, kind, mods)` (`scenes/combat.js`) threads `mods` into `new Combat(run, ids, {kind, mods})`. The Combat constructor applies **pure-data** enemy tweaks (`enemyHpMult` scales all enemy HP; `nemesisId` renames one enemy `Rendered <name>` + pads non-boss HP 30%, bosses 0 pad); `start()` applies grants needing the mounted view (`_nemesis` → +2 Resolve, `enemyResolve`, `playerStartBlock` via `gainBlockTo(player,n,true)`) — never fire `applyPower`/`fx` mods in the constructor, defer to `start()`. **#18**: `run.actFlags` (`{hardened?,blessed?}`, persisted, reset per act in `map.js` `nextAct()`) set by `data/events.js` choices (loot→`hardened`, mercy→`blessed`), read in `startMonster`/`startElite` (→`enemyHpMult:1.2`) and `startBoss` (→`playerStartBlock:12`). **#19**: the killer is saved to `meta.lastNemesis` (`{id,name,act}` in `save.js` defaultMeta) from `end.js` `gameOver` via `combat.lastAttackerId` (set in `applyDamage` only when the source is a foe, not self-damage); the next run's first elite becomes a solo buffed `[nemesisId]` fight (`nemesisForThisFight()`, gated once-per-run by persisted `run.nemesisDone`, id must still exist in `ENEMIES`); besting it pays +40 gold and clears `meta.lastNemesis`. Aura = `.combatant.nemesis` gold halo toggled in `combatView.updateCombatant` beside `.phased`/`.enraged`. **Verify gotcha**: drive run→map→elite as *separate* `page.evaluate` calls with Node-side waits (a single long in-page evaluate throttles the rAF that renders combat, so the aura class never lands), and `startElite()` needs a `showMap()` first or it won't mount combat.

Honors `prefers-reduced-motion` (reveal shown, flight skipped). Styles under the "relic acquisition reveal" block in `styles.css`.
- **Card-choice ("pick a card") popup** (`Game.cardChoiceOverlay` in `game.js`, `.card-picker` in `styles.css`) has no boxed panel — `.overlay-box.card-picker` zeroes out the shared `.overlay-box` background/border/border-radius/box-shadow so the title/cards/hint/Skip sit directly on the dimmed `.overlay` backdrop. It uses fixed-aspect-ratio cards (`height:/width: var(--card-h)/var(--card-w)`, not the shop/deck overlays' `height:auto;min-height:` grow-to-fit-text trick) so options read as normal cards instead of stretched slabs with dead space. `--card-h` is `clamp(232px, 25vw, 320px)` on `.card-picker` — floors high enough on narrow phones that even the longest card text (`the_long_song`, ~106 chars) fits; `.card-desc` is top-aligned (`align-items:flex-start`) there so if a description *does* overflow it trims cleanly off the bottom instead of a centered clip eating both the start and end of the sentence. Tapping a different card switches the selection instead of confirming. `.overlay-box`'s existing `overflow-y:auto`/`max-height:88vh` already makes the whole popup scrollable, which is what saves the layout on short landscape phones (812×375) where the fixed card height doesn't leave room for the hint + Skip button — confirmed via `box.scrollTop` in a Playwright check, not a new mechanism.
- **Per-turn enemy damage cap ("Invincibility")**: a data-driven field `dmgCapPerTurn` on an enemy blueprint (see `heart_of_static`) caps total damage that enemy can take across a single *player* turn. `combat.makeEnemy` seeds `dmgTakenThisTurn`, `applyDamage` clamps + banks pre-block damage (emits a `warded` fx), and `startPlayerTurn` resets the counter. `combat.start()` mirrors the value into `powers.invincibility` purely so the pip shows the cap — it's display-only, never ticked. `strengthDown` ("Resolve Down") is a real player debuff now: enemies apply it (`void_chanter` "Unname", `sand_wraith` "Wither"), and `tickTurnDebuffs` saps `strength` by the stacked amount at end of turn, then clears it. When adding an enemy `pick`, prefer `rng.weighted([{value,weight}])` + the player-state helpers (`playerLowHp`, `playerBlocked`, `playerLacks`, `selfLowHp` in `enemies.js`) over fixed `turn % n` cycles. Note: The thorns (Backlash) damage mechanic when attacked has been deactivated entirely to reduce intransparency, and all enemy-move references to `thorns` have been removed.
- **Smarter-enemy blueprint hooks (all data-driven, one-shot, added 2026-07)** — three seams that make fights reactive instead of fixed cycles:
  - **Boss phase transitions**: `phase: { at: 0.5, name, log, onEnter(c,s) }`. `Combat.checkPhase(e)` is called from inside `applyDamage` (so *every* damage source — cards, orbs, poison — can trigger it), sets `e._phased` once when HP first crosses `at`, logs, fires `fx('phase')`, runs `onEnter`, then **re-picks the enemy's intent** so the telegraph reflects phase 2 immediately. Branch the blueprint `pick()` on `s._phased` for the phase-2 move table. All three bosses (`the_gatekeeper`, `the_archivist`, `heart_of_static`) have phases. Gotcha: block granted by `onEnter` during the *player's* turn is wiped by `enemyPhase`'s `e.block = 0` before the enemy acts, so it only shields the remainder of the current player turn — a deliberate "shields up on transform" beat, not a bug.
  - **Summoning**: `Combat.summonEnemy(id, {max=4})` pushes a fresh enemy mid-combat (board-capped), gives it an intent, and sets `e._justSummoned` so `enemyPhase` skips it for exactly one phase (it's telegraphed during the intervening player turn). The view has **no pre-built node** for a summoned foe, so `combatView.update()` builds one lazily: any living enemy whose `els[id]` is missing gets a `buildCombatant` + `.summoning` entrance class. `fx('summon')` fires synchronously *before* that node exists (notify() is a microtask), so its ring/burst is deferred via a tiny `setTimeout`. Summoner + minion live in `enemies.js` as `choir_master` + `echo_mote` (Act 3, added to `ENCOUNTERS[3].normal`).
  - **Enrage**: `enrage: { turn, strength }` — `enemyPhase` grants the Resolve once, on/after that enemy's own `turn`, with `fx('enrage')`. On `brass_colossus` + `chrome_archon` (Block-heavy elites that could otherwise be stalled indefinitely). `_phased`/`_enraged` also drive persistent `.phased`/`.enraged` CSS auras, toggled in `updateCombatant` so they survive in-place re-renders.
  - **Crowded-board layout**: summoners can put 3+ foes on the enemy half (which is only ~half the viewport wide), so they wrapped down into the hand. Fix lives in `combatView.update()` (toggles `.enemies-3`/`.enemies-4` on `.enemy-side` by living-enemy count) + `styles.css` (those classes shrink the `--med` token, which drives every combatant sub-size, so 3–4 fit one row at both 1280px desktop and 812×375 landscape-phone). If you add a bigger summon or raise the board cap, re-check both widths.
- **Never use emoji in-game.** All iconography is custom SVG line-art in `src/ui/icons.js` (or a real sprite via `src/ui/sprites.js`) — no emoji characters in data files (`enemies.js`, `characters.js`, `keywords.js`) or UI code, even as unused/dead fields. The one real bug found and fixed here: `combatView.js`'s `power` fx handler was calling `floatText(..., def.icon, ...)`, rendering the raw emoji from `POWERS[key].icon` as a floating combat number. Fixed by adding `floatHTML()` to `fx.js` and rendering `<i class="pip-ic">${powerIcon(key)}</i>` (the existing SVG icon helper, same pattern already used for on-board status pips) instead. Typographic dingbats (`❖ ❘ ✦` in `game.js`, used as plain decorative dividers) and emoji in `tools/gen-*.js` console-log output are out of scope — they're not pictographic and never reach the player.
- **CSS comment trap that silently ate a whole `@media` block for a long time**: never let an asterisk and a slash land next to each other inside a `/* ... */` comment (e.g. writing `--card-*/--med` to mean "the `--card-*` and `--med` custom properties"). The `*/` closes the comment early; everything after it up to the next `{` — including the real `@media (...) {` that follows — gets swallowed as the prelude of one bogus, invalid selector, and the browser silently discards the whole rule (it won't error in the console). This is invisible in a text diff and doesn't break `node --check` (that's JS, not CSS) — the only way to catch it is to actually inspect parsed rules (e.g. `document.styleSheets` / `CSSMediaRule` in a live page) or eyeball the rendered layout at that breakpoint. `@media (max-width: 760px)` in `styles.css` (the narrow-portrait-phone rules: battlefield single-column, char-grid single-column, `.map-legend`/`.map-title` sizing, etc.) was dropped this way for a long time before being fixed — if a breakpoint's styles ever seem to have zero effect despite matching the media condition, suspect this before anything else.
- **Map (`showMap()` in `game.js` + the "map" section of `styles.css`)**: nodes are plain line-art glyphs (`NODE`/`NODE_ICON` in `src/ui/icons.js`) with no circular badge behind them — sizing is entirely on the `.map-node` wrapper div (`.map-node .svg-ic` just fills most of it), so "bigger node" is "bigger wrapper," and `.map-node.current`/`.node-boss` just use larger width/height rather than a `transform: scale()` (scale would fight the `:hover`/pulse transforms, which only ever translate/scale from the *reachable* state). The bottom row (row 0) must never contain more than 3 starting options, enforced in `src/map/mapgen.js` by sampling at most 3 starting columns (`Math.min(COLS, 3)`) using `rng.sample`. Each node's on-board position gets a small deterministic pixel jitter (`jitter(row, col)` in `showMap()`, hashed from row/col — not `Math.random()`, so it's stable across re-renders and the SVG edges — drawn from the same `posOf()` helper — always terminate exactly on the jittered icon center) so the layout reads hand-drawn instead of gridded. The map scene is a fixed-height flex column (`.scene.map { height:100dvh; overflow:hidden }` → `.map-scene` flex:1 → `.map-scroller` flex:1 with its own `overflow-y:auto`) so only the inner scroller scrolls and the board always reaches the bottom of the viewport; using `min-height` instead of `height` here breaks this — the flex item is then free to grow past the container instead of scrolling internally, and the whole *page* scrolls instead (topbar and header included). **Art-direction pass (2026-07):** there is no headline/`​.map-header` anymore (act name lives only in the top bar); the act backdrop shows at `opacity:0.2` (`body.scene-map #bg-image`) with a more translucent `.map-scroller` gradient so the painting reads behind the board. The legend is an **always-on framed panel** (`.map-legend` `<aside>` built in `showMap()`) pinned to the right of the board inside a `.map-body` flex row (scroller flex:1 + fixed-width legend); it has a `.map-legend-head` title + `.map-legend-list` of simple icon+label rows (no descriptions) and an ornate double-border/corner-tick frame. On `max-width:760px` `.map-body` stacks to a column and the legend reflows to a compact horizontal chip strip below the board; on `max-height:560px` it stays a trimmed right column. Per-edge connector ornaments (a faint `.edge-dot` diamond at the midpoint + a `.edge-arrow` chevron rotated toward the target at ~72%) and node accents (concentric ring `::before` on `.current`/`.node-boss`, twinkling sparkle `::after` on reachable + boss, disabled under reduced motion) are all deliberately subtle. The top-bar `.tb-fs`/`.tb-mute` buttons are circular with a faint inset ring — global chrome, shown on every scene, so QA's combat shot guards against regressions.
- **Port conflicts (`EADDRINUSE`) during QA audit**: If the static server fails to bind to port 8091 because of lingering/zombie processes, run the audit specifying a different port prefix, e.g., `QA_PORT=8095 npm run qa`.
- **Text contrast on title/scenic backgrounds**: Any overlay text or toggle buttons rendered over scenic background art (such as the bright lines on the title screen) must have a dark semi-transparent backing card/pill background (like `rgba(8, 5, 3, 0.85)`) to block out light lines and ensure contrast.

No new meta keys needed — thresholds are checked live against the existing `meta.wins` counter.

This is implemented via an absolute `::after` overlay utilizing a screen blending radial-gradient (bent sphere reflection) and a smooth position tracking transition linked to the mouse cursor position. For custom button shapes with non-rectangular bounds (polygons), the `::after` overlay must match the exact parent `clip-path` polygon. Disable these hover animations in the `@media (prefers-reduced-motion: reduce)` block.
- **Card Selection UID Comparison**: Always compare active preview or pending cards (`this.previewCard` / `this.pendingCard`) against hand card items using `.uid` (e.g. `this.previewCard && this.previewCard.uid === card.uid`) rather than strict object reference comparison (`!==` or `===`). This prevents keyboard selection issues where different card object references representing the same card would fail to play or toggle state correctly.
- **Combat-feedback fx conventions (2026-07 feedback pass)**: `combat.js` emits two additional purely-cosmetic fx types: `powerfade` (`{target, key}`, fired wherever a power is *silently deleted* — `consumeStack`, `tickTurnDebuffs`, `tickPoison`) and `reshuffle` (`{count}`, fired in `draw()` just *before* discard→draw so the handler can read both pile rects). View-side diff state on `CombatView` (`_lastHp`/`_lastPowers`/`_lastIntent`) drives the HP ghost trail (`.hpghost`), `.pip-pop` and `.intent-new` — pop classes are applied at node-build time so there is no rAF race with in-place re-renders. Big hits get an ~85ms `.hitstop` freeze + deferred shake in the view (`setTimeout`, never an engine `await`). CSS gotchas: `.hpfill` is a static child, so the absolutely-positioned `.hpghost` behind it paints on top unless `.hpfill` has `position: relative; z-index: 1`; `.intent` is centered by `transform: translateX(-50%)` and runs `intentBob`, so any new intent animation must carry `translateX(-50%)` in every keyframe and temporarily replaces the bob. The HP ghost freezes at its current rendered width before re-targeting, so multi-hit attacks can't jump it back up mid-drain.

Do not use flood-fill or dark threshold key-outs.

Supports arrow/WASD/Tab navigation, Escape for canceling, and numbers `1`-`9` as direct shortcuts (except during combat hand play). Emits synthetic `mouseenter`/`mouseleave` to drive tooltips/hover states. Focus class is `.kb-focus`. - **Rhythm QTE rules (src/ui/rhythm.js + combat.js)**: attack QTEs grade perfect/good/miss (×1.25/×1.0/×0.5 damage). The enemy-attack parry is only prompted when the player has block; a **missed parry halves the player's block** (`Math.floor(realBlock/2)`, then the hit consumes it normally — it must NOT void/restore block, that made Block cards worthless on a miss; regression tests in tools/test.js). The view floats `BLOCK HALVED` via the `parrymiss` fx. Desktop mice can now also answer directional marks by **clicking on the chevron's side of the QTE ring** (stationary click ≥26px off ring-center in `onPUp`; near-center clicks stay 'tap'). The rhythm toggle lives on the title screen (`Game.setRhythm`); attack QTEs read `rhythmOn()` per card play, but the parry prompt is bound once per combat, so `setRhythm` must call `combatView.bindParryPrompt()` to apply mid-fight. Husk Drone `startBlock` is 6 (was 12 — the tutorial's coached first attack did no visible HP damage). **QTE-result banner must not delay the strike's SFX/VFX**: `runAttackQTE` used to `await showResult(...)` (a 700ms banner hold) before resolving, so the actual attack's sound/particles — fired by `combat.playCard` right after `combatView.playCard` awaits the QTE — landed ~700ms after the player's timed input. Fixed by resolving `runAttackQTE` as soon as the grade is computed (adding a `qte-clear` class that instantly fades the dimming scrim + stage via CSS transition) and letting the result banner + `ui.destroy()` play out in the background via a detached `.then(...)` instead of being awaited.
- **Tempo (rhythm layer → card game, combat.js)**: a player-only counter stored as the `tempo` **power** (so pips/tooltips/`fx('power')` floats come free — no bespoke UI). Clean strikes build it (+1, +2 on Perfect), a successful parry adds +1, any missed beat (strike QTE or parry) **breaks it to 0** (`breakTempo()`, `RHYTHM BROKEN` float via the `tempobreak` fx); capped at 10 (`TEMPO_CAP`). The view sets `combat._rhythmGrade` next to `_rhythmMult` after the attack QTE; `Combat.playCard` consumes it for attacks via `registerStrikeGrade()` — **a null grade counts as 'good'**, so headless/Rhythm-off play still builds 1 Tempo per attack and Tempo cards never go dead. Registration happens **before** `onPlay`, so a Tempo-scaling card counts its own strike and a missed finisher fizzles (breaks first, then deals ×0.5) — deliberate risk/reward, don't "fix" it. Cards use `ctx.tempo()` / `ctx.gainTempo(n)` / `ctx.spendAllTempo()`; relics listen on the `tempoGained` trigger (`{ amount, total }`). Amara is the specialist (flowing_edge, dancers_poise, spiral_finish, war_drum_cadence, unbroken_dance in her pool) but the system is game-wide (pulse_stone / drummers_bangle relics work for any champion). Logic tests live in the "Tempo" group of `tools/test.js`.
- **Hit-counted debuffs (divergence from StS, combat.js + keywords.js)**: Exposed (`vulnerable`), Sapped (`weak`) and Brittle (`frail`) are **consumed per event, not per turn** — one stack per attack hit taken / attack hit made / card Block gain (multiplier unchanged: +50% / −25% / −25%). They have **no `ticksDown`** flag, so `tickTurnDebuffs` never touches them; consumption lives in `applyDamage` (`consumeStack`, blocked hits still consume) and the two `gainBlock*` paths. `calcAttackDamage` still *reads* stacks without consuming — it doubles as the next-hit preview math, so don't move consumption in there. **Blight spreads on death**: `onEnemyDeath` moves a dead foe's remaining Blight to a random living enemy (via `applyPower`, so Charm can negate it); the Blight Bloom power replaces the spread with an instant burst on ALL others. Snared/Sundered stay turn-ticked (inherently turn-based). Tests in the "Divergent statuses" group of `tools/test.js`. When adding cards/enemies, treat debuff amounts as **hit counts**, not turn counts — 1–2 stacks is the normal band.
- **Smooth Enemy Repositioning**: When an enemy is defeated, their `.dying` transition collapses their `min-width`, `max-width`, `width`, and `margin-left`/`margin-right` to `0` over `0.62s`. This allows the remaining flex children in `.enemy-side` to slide smoothly into their centered positions rather than hopping abruptly. The negative margins are sized to half of `--enemy-gap` to offset the flex container's gaps exactly.
- **Event scene audio dependency**: `src/scenes/event.js` calls `audio.play()` while resolving choices that change gold/remove cards. Keep `import { audio } from '../audio.js';` in that scene and cover gold-changing event choices in `tools/test.js`; otherwise a choice can mutate run state, throw before `resultThenMap()`, and stay clickable for repeated rewards/costs.
- **Lost Pointer Capture**: When card nodes (or any nodes capturing pointer events) are removed from the DOM or rebuilt during a state update while pointer capture is active, the browser fires a `lostpointercapture` event. Since `pointerup` or `pointercancel` may not fire on the node after it's removed, you must always listen to `lostpointercapture` to cleanly reset drag/gesture state (e.g., `this.drag = null`) and prevent permanent input locks.
- **Block/parry QTE scales with attack size, and is color-coded blue** (rhythm.js
  `runParryQTE({marks})` + `combatView.js` `parryMarksFor(e)`): a plain single
  hit is still one any-direction tap, but bigger attacks get a short sequence
  of timed **directional** swipes — one shot per blow (`marks = min(3, hits)`),
  plus a floor of 2/3 marks for a single heavy nuke (`dmg>=20`/`dmg>=30`) even
  at hits=1, so telegraphed boss swings still read as a harder parry. Any miss
  in the sequence fails the whole parry (same halve-block penalty as before).
  `buildQTE`'s `verb` becomes `'SWIPE'` (not `'TAP'`) for touch once a parry
  goes directional, since a tap can't convey direction. **Color split**: the
  parry/block QTE uses the `--blue`/`--blue-bright` accent (matches
  `float-block`'s `#9fc2ff` / the skill-card-upgrade border `#bcd6ff`) via
  `.qte-parry` overrides on target/note/label/beats/pop/result, vs. attack
  QTEs' `--orange`/`--amber`. The `.qte-dir` swipe arrow and `.qte-rings`
  backdrop are baked-color SVGs (not `currentColor`), so instead of forking a
  second SVG constant just for this recolor, `.qte-parry .qte-dir` and
  `.qte-parry .qte-rings` apply `filter: hue-rotate(190deg) saturate(1.15)` to
  shift the baked ember tones to blue (verified empirically against a plain
  swatch — hue-rotate is a matrix approximation, not a literal HSL rotation,
  so don't assume an arbitrary angle without checking the actual rendered
  color first). **Gotcha hit while verifying this in the browser preview**:
  `preview_start` snapshots `styles.css` at page load — CSS edits made *after*
  that are invisible in the running tab (getComputedStyle still returns the

  without reloading first silently show stale styling with no console error.

  and tears itself down with no visible trace — `preview_eval` +
  `preview_screenshot` round-trips are often slower than that, so the overlay

## Parallel Claude sessions — one worktree each
Multiple interactive Claude/agent sessions must **never share this checkout**:
branch, index and stash are global per working tree, so one session's
`git reset` / `git stash` / branch switch silently clobbers another session's
staged work mid-commit (this really happened — two sessions on this folder
produced mixed-scope commits and a mid-commit index reset). Give every session
its own worktree instead:
- `tools/worktree.sh new <topic>` → creates `../spire-wt-<topic>` on branch
  `claude/<topic>` off a freshly fetched `origin/main`, symlinks the primary
  checkout's `node_modules` into it (the game is dependency-free; the symlink
  is only for `npm run smoke` / `npm run qa`'s ambient playwright), and prints
  a stable per-topic dev port (8100–8199) plus `QA_PORT` (+100) so parallel
  `npm start` / `npm run qa` runs don't collide — 8080/8091 stay reserved for
  the primary checkout.
- Open the printed folder in the new Claude session and work normally there
  (commit, push, PR into `main`, self-merge; deploys still only trigger from
  `main`).
- After the merge: `tools/worktree.sh done <topic>` removes the worktree and
  deletes the branch if merged. It drops the `node_modules` symlink first —
  git refuses to remove a worktree containing untracked files otherwise.
- `git worktree list` will also show IDE-managed worktrees
  (`.claude/worktrees/...`, Antigravity's `~/.gemini/antigravity/worktrees/...`);
  they belong to those tools — leave them alone.
- The primary checkout should sit on `main` and mostly just `git pull`. If a
  session must run directly on it, treat it as read-only for git state.
- Gotcha: `.gitignore` must contain `node_modules` **without** a trailing
  slash — `node_modules/` only matches real directories, so the worktree's
  symlink would show up as untracked noise in `git status`.
- **A sibling session can rename shared vocabulary out from under your
  in-flight branch, invisibly** — this really happened (a repo-wide
  Exhaust→Consume rename landed on `main` mid-PR from another session). Your
  branch still tests green locally (it predates the rename), because GitHub
  Actions' `pull_request` trigger checks out `refs/pull/<n>/merge` (a
  synthetic merge of your head into *current* `main`), not your branch tip —
  and a clean, conflict-free git auto-merge won't flag that your added code
  now calls methods that no longer exist. If CI fails in a way you can't
  reproduce against your branch alone, fetch and test the actual merge ref:
  `git fetch origin +refs/pull/<n>/merge:refs/remotes/pull/<n>/merge`. See
  CLAUDE.md's "Parallel Claude sessions" section for the full incident + fix.
- **A fresh worktree has no `.env` either** (same reason as `node_modules`:
  it's gitignored/untracked, so only the primary checkout has it unless
  something symlinks it in). `tools/worktree.sh new` symlinks the primary's
  `.env` and `tools/node_modules` (openai/sharp, needed for the live asset
  generators) alongside `node_modules`; `done` removes all three. **IDE-managed
  worktrees** (`.claude/worktrees/...`) are *not* created by `tools/worktree.sh`
  and get none of these symlinks — if a live `OPENAI_API_KEY`-gated script
  reports the key missing there, check `/Users/moritzgrassy/spire/.env` in the
  primary checkout before assuming the key isn't set anywhere, and symlink
  (or copy) it and `tools/node_modules` into the worktree manually.
- **Encounter difficulty tiers (weak/normal/hard)**: monster fights escalate *within* an act. `startMonster()` (`src/scenes/combat.js`) picks the tier from the per-act fight counter `run._actMonster` — fights 1–2 `weak`, 3–4 `normal`, 5+ `hard` — and `pickEncounter()` (`src/scenes/map.js`) falls back to `normal` when the act's table defines no `hard` pool. `_actMonster` is persisted in the run save as `actMonster` (`state.js` toJSON/fromJSON) so a reload mid-act doesn't reset the run to weak fights. Only Act 1 has a `hard` pool so far — added because Act 1 went flat once the deck outgrew its many low-HP normals (spark_imp was 8–11 HP; several fights totaled <40 HP). When retuning, aim for total-HP bands of roughly weak ≲ 30 / normal ~30–65 / hard ~45–85, and keep packs to **two** enemies — no encounter has ever shipped 3, so the `.enemy-side` layout at landscape-phone widths is unproven for it.
- **Silent enemy side-effects need telegraph + feedback, not just state mutation** (Market Thief's `swipe`): give the move a distinct `intent.type` (e.g. `attacksteal`) rendered as an extra icon in `renderIntent` (`combatView.js`), register it in `INTENT`/`INTENT_INFO` (`icons.js`) and the `.intent-*` selector lists in `game.js`, and fire a dedicated `fx` (e.g. `c.fx('gold', {amount})`) from the move's `run()` using the *actual* amount applied (state can clamp, e.g. `run.gold` floors at 0). Any `fx` that needs to flash/float over a **top-bar** element can't do it inline in `onFx` — `CombatView.update()` fully rebuilds the top bar every tick, so the target node doesn't exist yet at fire time. Queue it and drain the queue in a small `applyFooFx()` called right after the topbar rebuild in `update()`, mirroring the existing `_pendingRelicPulses`/`applyRelicPulses()` pattern. Also: `Combat.pickEnemyMove` never merged the move's `name` onto `e.intent`, so `renderIntent`'s `wrap.title = it.name` was dead code (always blank) for every enemy — fixed by spreading `{ ...move.intent, name: move.name }`.
